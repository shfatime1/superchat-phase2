SuperChat combines Flights, Shopping and Cinema in a single responsive chat page. The user can switch topics, return to earlier selections, ask contextual follow-ups, or combine domains without selecting a mode. Phase 1 uses the five supplied JSON files. Part 3 reuses the existing backend and adds the browser interface and final integration.

Browser integration

FastAPI serves the frontend at / and assets at /static. The chat uses POST /api/chat; it renders the returned result structures, not facts inferred from prose. Cards expose quantities, comparisons, cart changes and mock reservations. A sidebar preserves conversations; the mobile layout uses a collapsible navigation drawer and a pinned composer.

Boundaries

The competition clock is fixed at 2026-11-02. There are no real-provider APIs, payments, accounts, voice or visual search. Render configuration and a portable PORT-aware start command are prepared; no push, provisioning or deployment was performed.

Grounded response formulation

A second Gemini call selects approved phrasing for the deterministic outcomes. Python inserts catalogue facts, money, stock, seats and confirmation IDs. Invalid or unavailable response planning falls back to templates, preserving completed operations. Existing English, Azerbaijani and Russian templates remain; full multilingual routing and UI translation are not added.

503/504 handling

The configured alias remains gemini-flash-latest. Auto mode uses an 8-second routing timeout, one SDK attempt and a 60-second circuit breaker after provider failure or invalid output. Calls during that window use local routing. Response planning has a separate 4-second timeout. Offline mode makes no Gemini calls; strict mode exposes sanitized 503/502 errors for diagnostics.

The previous live smoke test returned HTTP 504 for all four domain/mixed requests and HTTP 503 for a minimal generation call. It produced no usable classifications. A documented model alias does not establish availability for this key or a successful live integration.

Conservative outage coverage

The local parser recognizes common English domain terms, official IDs, known catalogue names, common dates and simple contextual references. It can split clearly separated mixed requests. Mutations require a fully recognized limited grammar and explicit quantities; negation, conditions, uncertain qualifiers and unknown selections lead to clarification. This sacrifices recall to avoid unintended cart or seat changes.

SuperChatState and data integrity

Keep each plan intact.

Each session owns separate Flights, Shopping and Cinema state: parameters, ordered results, selections, pending actions, cart and mock reservation records. Shared state stores language, explicit preferences, history and last active domain. An explicit return restores the named domain; a mixed turn clears the single implicit target so an unqualified follow-up cannot arbitrarily choose one domain.

Refresh and browser isolation

An unguessable HttpOnly, SameSite=Lax cookie identifies a browser. The server binds sessions to that identity; a session UUID alone is insufficient to retrieve another browser's data. An opaque namespace separates browser storage after cookie changes. LocalStorage retains IDs, structured turns and pending requests. Refresh fetches the latest server snapshot. Ended sessions remain readable as archived browser history.

This is anonymous browser isolation, not authentication. People sharing a browser profile share its saved conversations. Server state is in memory and does not survive process restarts; no private personal or payment information is required.

Atomic changes and interrupted requests

Per-session locks prevent lost updates. A shared, locked seat ledger checks and subtracts successful reservations across all sessions in one process. Unexpected turn failures roll back inventory. Each UI request carries a UUID; identical retries return the committed response once, including its original confirmation. Reusing a request ID for another payload is rejected. Deduplication lasts only for that process.

SuperChatVerification, limitations and references

Evidence and practical limits

200 pytest tests passed, including the original 160 tests and 40 Part 3 tests. Gemini is mocked in automated tests. Coverage includes repositories, domain operations, switches, follow-ups, mixed requests, isolation, quantity limits, outage handling, cookie ownership, concurrent retry deduplication and PORT configuration. One upstream Starlette/httpx deprecation warning remains.

Headless Microsoft Edge checks exercise desktop and mobile layouts, structured cards, comparisons, cart updates, mock tickets, sold-out controls, domain returns, refresh, new conversations and archived sessions. A simulated response loss after a reservation commits verifies safe retry. Browser screenshots support visual review.

The reproducible local category evaluation scored 32/36 (88.9%) on a hand-written English development corpus. Four vocabulary challenges were clarified instead of classified correctly. This is not a held-out benchmark or Gemini accuracy figure. The routing log includes every case and distinguishes mocked tests, local classification and unsuccessful live calls.

Known limitations and deployment readiness

  • Server sessions, ownership, retry records and inventory are process-local, unbounded and lost on restart. Run exactly one worker and one instance.
  • The inventory transaction also covers response planning for rollback consistency; slow model calls can serialize turns. This is suitable for a competition demo.
  • Local fallback has limited English coverage. Existing localized response templates do not imply full multilingual routing or a translated interface.
  • Live Gemini classification remains unverified while unavailable. Recheck the key/model before a provider-backed demo. All reservation confirmations are mock.
